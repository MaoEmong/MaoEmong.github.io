01 / CONTEXT

어떤 문제에서 시작했나요?

하루를 기록하는 앱이 매번 수동 입력을 요구하면 남기려던 순간을 놓치기 쉽습니다. 하루 기록은 기기에서 위치 흐름을 모아 사용자가 나중에 조용히 돌아볼 수 있는 기록을 만드는 앱입니다. 지도 자체보다 어느 시간에 이동했고 어디에 머물렀는지를 읽기 쉽게 정리하는 것이 중심입니다.

하지만 위치 좌표는 곧바로 일상의 기록이 되지 않습니다. 정지 중 GPS 튐, 낮은 정확도, 중복된 머문 곳 후보, 아직 일별 처리가 끝나지 않은 오늘 데이터가 화면을 왜곡할 수 있습니다. 원본을 보존하면서 표시용 경로와 추론 결과를 분리하고, 준비된 정보를 순서대로 보여주는 구조로 이 문제를 다룹니다.

02 / PRODUCT FLOW

사용자에게 이어지는 흐름

01

자동 위치 기록

Android의 백그라운드 위치 기록과 권한·알림 설정을 다룹니다.

02

하루 단위 돌아보기

오늘의 기록, 이동 경로 재생, 날짜별 요약과 상세 화면을 제공합니다.

03

장소와 로컬 데이터

부정확한 좌표를 걸러 내고 머문 곳 후보를 정리합니다. 사용자가 저장한 장소와 SQLite 데이터를 관리합니다.

한 번의 사용을 따라가 보면

  1. 01

    권한과 기록 기준 설정

    사용자가 위치·백그라운드 위치·알림 권한을 허용하고 기록을 켭니다. 움직임 거리와 머문 시간을 조정해 이동과 체류를 판단하는 기준을 정합니다.

  2. 02

    오늘의 상태를 먼저 확인

    오늘 화면에서 기록 상태와 거리·방문 수를 확인합니다. 무거운 좌표 계산이 끝나기 전에도 화면을 그리고 준비된 섹션부터 갱신하는 흐름을 사용합니다.

  3. 03

    경로와 장소 흐름 돌아보기

    오늘 기록과 하루 상세에서 정리된 이동 경로와 방문 기록을 봅니다. 흐름보기는 시간에 따라 좌표를 재생해 하루를 다시 따라가게 합니다.

  4. 04

    후보를 내 장소로 저장

    추론된 머문 곳을 확인하고 사용자가 직접 장소를 저장합니다. 기존 장소와 매칭된 후보에는 이름을 표시하고 새 장소와 구분합니다. 장소 목록에서는 이름·방문 횟수와 지도 미리보기를 확인합니다.

  5. 05

    날짜별 기록과 데이터 관리

    일별 처리가 만든 요약과 돌아보기를 날짜별로 열어 봅니다. 설정에서는 기록 조건과 알림, 데이터 삭제를 조정합니다. 공개 스크린샷은 데모 데이터로 재현한 화면입니다.

03 / ARCHITECTURE

구조와 책임을 나눈 방식

  1. 01

    수집과 기동 시 동기화

    Android foreground service에서 위치 기록을 수집하고 앱 시작 때 대기 중인 위치 이벤트를 SQLite로 가져옵니다. AppDependencies는 미처리된 전날 좌표가 있는지 확인해 필요한 경우 일별 처리를 수행하며, 설정과 실제 기록 상태를 조정합니다.

  2. 02

    원본과 표시용 데이터

    원본 LocationPoint는 SQLite에 저장합니다. LocationPostProcessor는 mock·유효하지 않은 좌표·낮은 정확도를 걸러내고 표시용 경로 정리와 머문 곳 추론에 전달합니다. 장소 이름과 기존 장소 매칭은 좌표 경로와 다른 책임으로 다룹니다.

  3. 03

    오늘 프리뷰와 확정 기록 조합

    DayActivityPreviewRepository는 일별 요약·저장된 방문·현재 원본 좌표를 읽고 추론 결과를 병합합니다. 이미 저장된 방문과 중복되는 후보를 제거하고, 알려진 장소라면 이름을 붙입니다. 좌표가 많으면 Isolate로 계산을 넘기는 경로가 있습니다.

  4. 04

    화면별 상태와 일별 처리

    Riverpod provider를 나누어 오늘 화면과 상세 데이터가 하나의 비동기 작업에 모두 묶이지 않도록 구성합니다. Workmanager 기반 일별 작업은 요약·돌아보기·알림을 처리합니다. 요약과 돌아보기는 외부 AI 호출 없이 로컬 위치·방문·패턴 데이터를 가공해 만듭니다.

04 / ENGINEERING CASES

구현하면서 선택한 것

기능 목록 뒤에 있는 문제와 선택, 그 선택이 남긴 비용을 정리했습니다.

CASE 01

원본 좌표를 그대로 경로로 쓰지 않음

마주한 문제
GPS의 작은 튐을 모두 이동으로 계산하면 정지 중에도 경로와 이동 거리가 늘어날 수 있습니다.
선택과 구현
mock·좌표 범위·정확도를 먼저 검사하고 표시용 좌표는 별도 cleaner를 통과시킵니다. 머문 곳은 사용자의 거리·시간 기준으로 추론하고 기존 장소와 가까운 후보를 매칭합니다.
남은 비용과 한계
정제 기준이 강하면 짧은 이동을 잃을 수 있습니다. 정확도 상한과 장소 매칭 반경은 기기·환경별 평가를 바탕으로 조정해야 합니다.
LocationPostProcessor ↗
CASE 02

오늘 프리뷰에서 저장 기록과 추론 병합

마주한 문제
저장된 방문만 보여주면 오늘의 새로운 체류가 빠지고, 추론 결과를 모두 더하면 같은 장소가 중복됩니다.
선택과 구현
저장 방문과 추론 후보를 시간·위치 기준으로 비교해 병합하고 알려진 장소 이름을 적용합니다. 표시용 경로로 거리를 계산하며 좌표 80개 이상에서는 Isolate 계산을 시도합니다.
남은 비용과 한계
반경 기반 중복 제거는 가까운 서로 다른 장소나 같은 장소의 재방문을 합칠 수 있습니다. 프리뷰와 경로에서 중복으로 수행하는 계산을 공통화하는 작업도 남아 있습니다.
DayActivityPreviewRepository ↗
CASE 03

일별 작업의 재실행과 날짜 경계 검사

마주한 문제
백그라운드 작업은 같은 날 다시 실행되거나 자정을 넘는 체류 기록을 처리할 수 있어 중복과 날짜 오류에 취약합니다.
선택과 구현
같은 날짜 작업의 재실행, 다음 날 첫 좌표로 전날 체류 닫기, 같은 장소의 인접 조각 합치기를 검사하는 테스트를 구성했습니다. 메모리 SQLite와 가짜 알림 어댑터로 처리 후 상태를 확인하도록 했습니다.
남은 비용과 한계
결정적인 입력으로 처리 규칙을 검사해도 Android의 절전·권한 변경·프로세스 종료가 섞인 장시간 실제 수집 안정성은 별도로 검증해야 합니다.

05 / ROLE & CONTRIBUTION

맡은 역할과 기여

Flutter 앱의 위치 수집부터 로컬 저장, 좌표 후처리, 오늘 프리뷰와 날짜별 돌아보기까지 이어지는 흐름을 구성했습니다. 원본 좌표는 보존하고 표시용 경로와 머문 곳 후보를 별도로 만들어, 수집한 데이터와 사용자가 읽는 기록의 역할을 나눴습니다.

추론한 장소는 사용자가 확인하고 저장할 수 있는 후보로 표현했습니다. 오늘 프리뷰에서는 저장된 방문과 새 후보를 병합하고 중복을 줄였으며, Riverpod으로 화면별 비동기 상태를 나눴습니다. 일별 처리에서는 같은 날짜의 재실행과 자정 경계를 다루는 테스트 코드를 구성했습니다.
