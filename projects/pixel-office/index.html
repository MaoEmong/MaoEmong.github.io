01 / CONTEXT

어떤 문제에서 시작했나요?

여러 AI 터미널을 함께 사용할 때는 답변을 읽는 일보다 작업의 관계를 파악하는 일이 어려워집니다. 한 담당자가 조용한 이유가 검사 실행인지, 다른 담당자의 결과 대기인지, 사용자 허가인지 알기 어렵고, 대화가 끝났다는 이유만으로 일이 끝났다고 오해할 수 있습니다. 픽셀 오피스는 이 차이를 사무실의 담당자와 진행 기록으로 드러내는 데 초점을 맞춥니다.

기능을 많이 연결할수록 재연결·사용 한도·파일 충돌 같은 중간 실패도 제품의 일부가 됩니다. 0.2.5에서는 답변 누락, Windows Codex 입력 접수, 결과 대기 업무의 잘못된 완료 처리를 보완했습니다. 핵심은 AI의 성과를 대신 판단하는 것이 아니라, 관측한 상태와 사용자가 확인해야 할 일을 정확히 전달하는 것입니다.

02 / PRODUCT FLOW

사용자에게 이어지는 흐름

01

AI 팀과 결과 대기

담당자 사이의 대기 상대·필요한 결과·다음 행동을 표시하며, 결과가 모두 모이면 원래 대화에 재개 안내를 전달합니다.

02

질문·허가와 완료 보고

내 책상에서 실제 실행 내용을 확인하고 결정합니다. 답변·지시 접수·명령 실행·검사 통과·업무 완료를 구분합니다.

03

파일·문서와 복구

Markdown·텍스트 편집, 외부 변경 충돌 안내, 별도 로컬 Git 저장 지점과 확인 후 파일 복원을 제공합니다.

04

사용 한도와 작업 재개

기존 대화·업무를 보존하고 같은 AI로 재확인하거나 다른 AI에 진행 요약을 넘겨 이어갑니다.

한 번의 사용을 따라가 보면

  1. 01

    부서를 만들고 작은 목표 정하기

    작업 폴더와 사용할 AI를 고른 뒤 준비 상태를 확인합니다. 부장과 대화하며 원하는 결과와 완료 기준을 정하고, 팀별 의견·작업 계획·완료 단계를 살펴봅니다.

  2. 02

    담당자와 대기 관계 읽기

    캐릭터를 선택해 현재 업무, 필요한 상대의 결과와 결과 도착 후 할 일을 확인합니다. 부분 결과만 도착했거나 접수 확인이 없으면 남은 대기를 그대로 보여 줍니다.

  3. 03

    질문과 실제 실행 내용 확인하기

    내 책상에서 질문에 답하고 실행 허가를 결정합니다. AI끼리 주고받는 질문은 상사의 답변 대기로 구분해, 사용자에게 필요한 판단을 모읍니다.

  4. 04

    파일을 검토하고 문서 수정하기

    요청별 완료 보고·파일 변경·보고된 검사를 읽습니다. 앱 안에서 Markdown·텍스트 문서를 편집하고, AI가 같은 파일을 수정하면 작성 중 글을 유지한 채 비교 안내를 확인합니다.

  5. 05

    한도나 재시작 이후 이어가기

    사용 한도 소진 시 업무·대화·완료 단계와 파일을 보존합니다. 사용량 재확인 후 기존 AI를 재개하거나 다른 AI를 직접 선택해 요약과 남은 업무를 전달합니다. 단순 목록 선택만으로 작업을 재개하지 않습니다.

03 / ARCHITECTURE

구조와 책임을 나눈 방식

  1. 01

    화면과 실행 관리의 연결

    Flutter·Dart PC 화면과 Node.js·TypeScript 실행 관리 구조를 연결해 실제 AI CLI의 대화와 작업을 다룹니다. 부서마다 작업 폴더·부장·사용 AI를 고르고, 팀원→팀장→부장→사용자의 보고 관계로 업무를 정리합니다. AI 설치와 로그인은 각 CLI의 책임입니다.

  2. 02

    상태와 결과 의존 관계

    사무실은 담당자의 실행 상태와 누구의 어떤 결과를 기다리는지 표시합니다. 결과 도착, 지시 접수와 실제 후속 실행은 서로 다른 사건입니다. 열린 질문·허가·작성 중 입력·사용 한도·실행 중 명령이 있으면 재개 안내 이후에도 실행을 기다릴 수 있습니다.

  3. 03

    두 위치에 보관하는 기록

    앱 설정·조직·키·파일 저장 기록은 앱 데이터 폴더에, 프로젝트별 대화·작업 파일은 해당 폴더의 .pixel-office에 보관합니다. 재시작은 저장된 작업의 복구를 시도하며, 파일 저장 지점은 별도 로컬 Git 기록으로 관리합니다. 업데이트·백업에는 두 위치를 함께 다뤄야 합니다.

  4. 04

    사용자가 판단하는 작업 경계

    실행 허가는 내 책상에서 실제 명령과 요청자를 보고 결정합니다. 진행·기록에서는 완료 보고와 바뀐 파일, AI가 보고한 검사 결과를 함께 읽습니다. 실행 기록만으로 검사 통과를 표시하지 않으며, 사용량을 확인할 수 없으면 수치를 미확인으로 남깁니다.

04 / ENGINEERING CASES

구현하면서 선택한 것

기능 목록 뒤에 있는 문제와 선택, 그 선택이 남긴 비용을 정리했습니다.

CASE 01

결과 대기를 업무 완료로 바꾸지 않기

마주한 문제
담당자가 결과를 기다린다는 답변으로 턴을 마치면, 답변 종료와 업무 완료를 같은 사건으로 취급할 위험이 있었습니다.
선택과 구현
기다리는 상대·필요한 결과·다음 행동을 등록하고 모든 결과가 모일 때 원래 대화에 재개를 안내합니다. 부분·중복 결과와 재연결을 구분하고 명시적인 완료 보고 전까지 미완료 업무를 보호합니다.
남은 비용과 한계
상태를 보수적으로 유지하므로 사용자가 기록을 더 확인해야 할 수 있습니다. 등록되지 않은 대기 사유를 과거 답변에서 추측하거나, 재개 안내를 성공·허가로 확대하지 않습니다.
0.2.5 변경 내역 ↗
CASE 02

전송과 접수를 분리한 Windows 입력 복구

마주한 문제
한글·기호가 포함된 Codex 지시나 접수 전 재연결에서 입력을 보냈다는 사실만으로 실제 접수를 확정하기 어려웠습니다.
선택과 구현
입력 준비와 한글·기호 전달을 보완하고, 접수 신호가 빠지면 같은 대화의 저장 기록으로 정확한 접수를 확인합니다. 부장·담당자의 최종 답변도 연결 상태와 구분해 보존합니다.
남은 비용과 한계
조회 범위 밖의 접수나 이동된 기록은 미확인으로 유지합니다. 검증 문서의 저장 대화 재개 확인은 새 모델 요청 없이 수행한 검사이며 모든 AI 버전·연결 오류 복구를 보장하지 않습니다.
0.2.5 배포 검증 ↗
CASE 03

공유 작업 폴더를 되돌리는 절차

마주한 문제
여러 AI가 같은 폴더를 수정하므로 한 담당자의 작업만 저장했다고 표현하거나, 오래된 대화를 그대로 이어 복원 파일을 다시 바꾸면 위험합니다.
선택과 구현
프로젝트 전체 파일 상태를 원래 Git과 분리해 저장합니다. 복원·삭제 대상을 먼저 확인하고 겹치는 폴더의 AI를 멈춘 뒤 현재 파일을 안전 보관합니다. 복원 후에는 부장을 재고용해 현재 파일 기준으로 지시합니다.
남은 비용과 한계
대화·외부 DB·배포 상태는 복구하지 않으며 제외 파일과 저장 이력이 없는 새 파일에도 한계가 있습니다. 저장 중 파일이 바뀌어 완전한 상태를 확인하지 못하면 실패로 표시합니다.
파일 저장·되돌리기 범위 ↗
05 / ROLE & CONTRIBUTION

맡은 역할과 기여

여러 AI 도구를 함께 사용하며 겪은 불편을 제품 요구사항으로 정리했습니다. 담당자가 실행 중인지, 다른 결과를 기다리는지, 사용자 허가가 필요한지 구분하기 어려웠던 경험을 바탕으로 대화·완료 보고·대기·질문·허가의 기대 동작을 구체화했습니다.

AI 지원으로 구현과 검증을 진행하고 Windows 앱 패키징과 시험판 배포까지 연결했습니다. 답변 누락, 입력 접수, 결과 대기의 잘못된 완료 처리처럼 실제 사용 중 발견한 문제를 버전별 수정 항목으로 정리했습니다. v0.2.5 배포에는 다운로드 파일과 사용 안내, 패키지·복구 검증 기록을 함께 제공했습니다.

06 / EVIDENCE & LIMITS

무엇을 확인했고, 무엇이 남았나요?

프로젝트 검증 당시의 실행 기록과 코드에 구성한 테스트 항목을 정리했습니다. 각 항목에 실행 조건과 추가 확인이 필요한 범위를 함께 적었습니다.

프로그램·PC 앱 검사

v0.2.5 검증 기록은 내부 프로그램 1,655개 통과·17개 제외, PC 앱 996개 통과·1개 제외입니다.

서로 다른 검사 집합으로 각각 집계했습니다. 배포 당시의 자동 검사 결과와 제외 항목은 검증 문서에 정리했습니다.

검증 근거 보기 ↗

패키지·복구 확인

ZIP 구성품 1,943개의 목록·해시를 대조하고 Windows 시작·종료·복구 10항목을 확인했습니다.

같은 PC에서 사용자 데이터·실행 경로·포트를 분리한 환경이며 실제 AI 모델 호출은 제외했습니다. 다른 PC의 최초 설치와 로그인은 추가 확인 항목입니다.

검증 근거 보기 ↗

Windows 시험판 배포

v0.2.5 시험판에 Windows x64 ZIP과 SHA256 파일을 함께 배포했습니다.

공개 릴리스에서 패키지와 해시 파일을 받을 수 있습니다. 코드 서명과 다른 PC의 설치·로그인 검증은 남아 있습니다.

검증 근거 보기 ↗

현재 범위와 남은 과제

  • 현재 배포는 Windows x64 시험판입니다. 코드 서명, 다른 PC의 최초 설치·AI 로그인, macOS·Linux 배포는 후속 과제입니다.
  • 소개 화면은 실제 앱에 프로젝트·대화·검사·사용량 예시 데이터를 넣어 촬영했습니다.
  • 파일 복구는 저장된 로컬 파일을 대상으로 합니다. 대화·외부 DB·웹사이트·온라인 전송과 저장 전 입력은 복구 대상에 포함되지 않습니다.
  • 원본 개발 코드는 비공개입니다. 외부 CLI 버전별 호환성과 연결·명령 실패 사례를 계속 확인해야 합니다.

다음에 보완할 것

  • 다른 PC의 최초 설치·로그인과 실제 계정 조합별 장시간 사용을 검증하고 재현 조건을 공개 기록으로 남깁니다.
  • 대기·접수·재연결·한도 복구의 실패 사례를 배포 버전별로 축적해 사용자가 복구 범위를 판단할 수 있도록 보강합니다.
